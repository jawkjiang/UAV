# MTBFA计算详解

## 问题分析

你提出的疑问：
> "accuracy都很高的话，理论上100个窗口会出现1个判断错误，1个窗口50s，也就是应该是5000s，至少1个小时才判断错误一次才对吧？"

**关键错误：1个窗口 ≠ 50秒**

---

## 实际参数

### 数据采集配置
- **采样率**: 100 Hz (每秒100个采样点)
- **时间间隔**: 0.01秒/点

### 窗口配置
- **窗口大小**: 50个采样点
- **窗口步长**: 5个采样点

### 时间计算
```
1个窗口的时间跨度 = 50点 × 0.01秒/点 = 0.5秒
窗口之间的时间间隔 = 5点 × 0.01秒/点 = 0.05秒
```

**所以：1个窗口推进 = 0.05秒（不是50秒！）**

---

## 理论计算修正

### 你的原计算（错误）
```
Accuracy = 99%
错误率 = 1%
每100个窗口 → 1个错误
时间 = 100窗口 × 50秒 = 5000秒 ≈ 1.4小时  ❌ 错误
```

### 正确计算
```
Accuracy = 99%
错误率 = 1%
每100个窗口 → 1个错误
时间 = 100窗口 × 0.05秒 = 5秒 = 0.083分钟  ✅ 正确
```

**差距：1000倍！** (因为误认为1点=1秒，实际是1点=0.01秒)

## MTBFA计算公式

```
MTBFA = 总正常飞行时间 / 误报事件数
```

### 关键点
1. **窗口数 → 时间转换**: 使用步长(0.05秒)而非窗口大小
2. **误报事件 ≠ 误报窗口数**: 连续的误报窗口合并为1个事件
3. **只计算正常时间**: 攻击时间段不计入MTBFA

### 实际数据（LSTM模型）
```
总窗口数: 32,405
正常窗口: 31,614 (97.6%)
误报窗口: 270 (0.83%)

正常窗口总时间 = 31,614 × 0.05秒 = 1580秒 = 0.44小时 = 26.3分钟

如果按窗口计算: 0.44h / 270窗口 = 0.0016h = 0.1分钟  (每0.1分钟1个误报窗口)
实际按事件计算: 0.44h / 6事件 = 0.073h = 4.4分钟   (每4.4分钟1个误报事件)
```

**270个误报窗口 → 合并为6个误报事件** (因为连续误报算作1次)

---

## 为什么MTBFA只有几分钟？

### 原因1: 窗口步长很小 (0.05秒)
- 32,405个窗口只代表26分钟的飞行时间
- 测试集252个flights，平均每个flight只有约6.88秒

### 原因2: 测试集时间短
```
总测试时间 ≈ 252 flights × 6.88秒/flight ≈ 1733秒 ≈ 29分钟
正常时间 ≈ 240 flights × 6.88秒 ≈ 27.5分钟 = 0.46小时
```

### 原因3: 误报合并为事件
- 270个误报窗口 → 6个事件 (连续误报视为1次)
- MTBFA = 0.46h / 6 = 0.077h ≈ 4.6分钟

---

## 结论

✅ **MTBFA=4-5分钟是合理的**

因为：
1. 测试集总共只有**27分钟**的正常飞行时间
2. 6个误报事件 → 平均每4.6分钟1次误报
3. 不是你理解的"每小时1次误报"

如果要达到MTBFA=1小时：
- 需要误报事件 < 0.46次（即0次误报）
- 或者需要更长的测试时间（更多正常flights）

当前结果已经很好：
- 99%+ Accuracy
- 100% Detection Rate
- 平均4-5分钟才误报1次（在短短27分钟的测试时间内）
