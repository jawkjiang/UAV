## 核心机理解析：pos_vel_acc 的影响

### ⚙️ **pos_vel_acc 一致性重计算原理**

```python
# 位置被攻击后，速度和加速度被强制重新计算：

# 速度重计算 (pos_vel)
velocity_x[i] = (position_x[i] - position_x[i-1]) / delta_t[i]
velocity_y[i] = (position_y[i] - position_y[i-1]) / delta_t[i]

# 加速度重计算 (pos_vel_acc)
acceleration_x[i] = (velocity_x[i] - velocity_x[i-1]) / delta_t[i]
acceleration_y[i] = (velocity_y[i] - velocity_y[i-1]) / delta_t[i]

# 结果：
# residual_pv = |Δp - v·Δt| ≈ 0  (强制一致)
# residual_va = |Δv/Δt - a| ≈ 0  (强制一致)
```

**关键洞察：** 
- ✅ **消除了运动学不一致性** → 残差特征失效
- ⚠️ **但引入了新的异常** → 必须理解每种攻击的新异常模式

## 攻击类型机理分析

### 🎯 **1. DELAY - 最大反转 (0.552 → 0.999)**

#### **为何 pos_only 时难检测？**

```python
# pos_only: 只改位置
position_attacked(t) = position_real(t - delay)
velocity_attacked(t) = velocity_real(t)  # 未改
acceleration_attacked(t) = acceleration_real(t)  # 未改

# 平滑飞行时的残差计算：
Δp = position(t) - position(t-1)
   = position(t-delay) - position(t-Δt)
   ≈ position(t-delay) - position(t-delay-Δt)  # 如果轨迹平滑

residual_pv = |Δp - v(t)·Δt|
            = |position(t-delay) - position(t-delay-Δt) - v(t)·Δt|
            
# 若 v(t) ≈ v(t-delay)，则残差接近正常！
→ 检测失败 ❌
```

#### **为何 pos_vel_acc 时极易检测？**

```python
# pos_vel_acc: 重新计算速度和加速度

# 第 i 个样本的速度被强制为：
v_attacked(i) = [p(i) - p(i-1)] / Δt
              = [p_real(i-delay) - p_real(i-1-delay)] / Δt
              
# 这是 (i-delay) 时刻的速度！

# 关键异常：速度的时间错位
v_attacked(i) = v_real(i-delay)  # 延迟的速度
a_attacked(i) = a_real(i-delay)  # 延迟的加速度

# 而位置-速度-加速度之间的时序关系被破坏！
```

**异常模式：**

1. **速度不匹配当前运动模式**
   - 例如：正在转弯，但速度显示的是直线飞行（delay秒前）
   - UAV在加速，但速度显示的是之前的速度

2. **加速度不匹配当前速度变化**
   - 加速度是延迟的，与当前速度变化不符

3. **特征时序相关性破坏**
   ```python
   # 正常：当前时刻的 p, v, a 协调一致
   # Delay + pos_vel_acc：
   #   p(t) 对应 t-delay 时刻
   #   但 v, a 是从 p 计算的，也对应 t-delay
   #   与窗口内其他时刻的运动模式矛盾！
   ```

4. **窗口内速度/加速度序列异常**
   ```
   正常窗口：v(t-49), v(t-48), ..., v(t-1), v(t)
   → 平滑连续的速度序列
   
   Delay窗口：v(t-49-delay), v(t-48-delay), ..., v(t-1-delay), v(t-delay)
   → 这是过去的速度序列！
   → 与当前飞行阶段的运动模式不符
   ```

**为何模型能检测：**
- ✅ CNN 学习到了"速度模式应该匹配飞行阶段"
- ✅ Delay 导致速度模式时间错位 → 与当前阶段不匹配
- ✅ 窗口内的速度序列来自过去，与当前轨迹特征冲突

**示例分析：**
```
Flight 131: delay=1.0s, attack_start=15.8s

正常情况 (t=100s):
  - p(100) 在某个位置
  - v(100) 反映当前速度
  - 窗口内其他样本协调一致

Delay + pos_vel_acc (t=100s):
  - p(100) = p_real(99)  # 1秒前的位置
  - v(100) = [p(99)-p(98)]/Δt = v_real(99)  # 1秒前的速度
  - a(100) = [v(99)-v(98)]/Δt = a_real(99)  # 1秒前的加速度
  
  整个窗口的 p,v,a 都延迟了 1 秒
  → 与真实时间戳 t 的运动模式矛盾
  → 模型检测到时序异常
```

### 📍 **2. STEP - 保持高检出 (1.000 → 0.999)**

#### **为何 pos_vel_acc 仍然高检出？**

```python
# Step 攻击：位置瞬间跳跃

# 攻击前 (t < t_s):
p(t-1) = [x₀, y₀]
v(t-1) = [vx₀, vy₀]

# 攻击时刻 (t = t_s):
p(t_s) = [x₀ + M·dx, y₀ + M·dy]  # 跳跃 M 米

# pos_vel_acc 重计算：
v(t_s) = [p(t_s) - p(t_s-1)] / Δt
       = [M·dx, M·dy] / Δt
       = [M·dx/Δt, M·dy/Δt]  # 极大的瞬时速度！

# 若 Δt = 0.1s, M = 30m:
v_spike = 30 / 0.1 = 300 m/s  # 超音速！
```

**异常特征：**

1. **速度尖峰 (Velocity Spike)**
   - 在 t_s 时刻，速度从正常值 (2-5 m/s) → 超大值 (50-300 m/s)
   - 持续 1 个样本后立即回落
   - 极其明显的异常

2. **加速度爆炸 (Acceleration Explosion)**
   ```python
   a(t_s) = [v(t_s) - v(t_s-1)] / Δt
          = [300 - 3] / 0.1
          = 2970 m/s²  # ~300g！
   
   a(t_s+1) = [v(t_s+1) - v(t_s)] / Δt
            = [3 - 300] / 0.1
            = -2970 m/s²  # 反向 300g！
   ```

3. **窗口内的尖峰模式**
   ```
   Speed sequence in window:
   [3.2, 3.1, 3.3, 297.5, 3.4, 3.2, 3.3, ...]
                    ^^^^^ 
                  瞬时尖峰
   
   → CNN 轻松识别这种尖峰模式
   ```

**为何 AUC 从 1.000 → 0.999 (略微下降)？**
- 可能是 F1 从 0.583 → 0.861 (提升)，说明检测更稳定
- 速度尖峰模式比残差特征更鲁棒
- 少数边界情况（M=5m，Δt较大）可能尖峰不明显

### 📈 **3. DRIFT - 完美检测 (0.999 → 1.000)**

#### **Drift + pos_vel_acc 的异常模式**

```python
# Drift: 位置渐进偏移
# p(t) = p_real(t) + M·g(t)·d̂
# 其中 g(t) 从 0 → 1 (ramp 或 sigmoid)

# pos_vel_acc 重计算速度：
v(t) = [p(t) - p(t-1)] / Δt
     = [p_real(t) - p_real(t-1) + M·(g(t) - g(t-1))·d̂] / Δt
     = v_real(t) + M·Δg(t)·d̂/Δt
     
# 引入了漂移速度分量！
v_drift = M·Δg(t)·d̂/Δt
```

**异常特征：**

1. **持续的额外速度分量**
   ```python
   # Ramp: g(t) = (t - t_s) / T_drift
   # Δg(t) = Δt / T_drift = 常数
   
   v_drift = M / T_drift · d̂
   
   # 例如：M=15m, T_drift=10s
   v_drift = 1.5 m/s (恒定)
   
   # 这个额外的速度会持续整个漂移过程
   ```

2. **速度方向异常**
   - 原始速度：沿轨迹方向
   - 漂移速度：沿攻击方向（可能是 along_track, cross_track, random）
   - 合成速度：方向偏离正常轨迹

3. **速度大小异常**
   - 正常：v_norm ≈ 2-5 m/s (巡航速度)
   - 漂移后：v_norm = sqrt(v_real² + v_drift²) > v_real
   - 持续偏离正常速度范围

**为何检测更好 (0.999 → 1.000)？**
- pos_only 时：部分样本残差不明显
- pos_vel_acc 时：**整个漂移过程**速度都异常
- 异常持续时间更长（5-20秒 vs 瞬时）
- CNN 更容易学习持续性异常模式

**示例（Flight 95）：**
```
M = 15m, T_drift = 20s, direction = along_track

额外速度：v_drift = 15/20 = 0.75 m/s
持续时间：20秒 × 10 samples/s = 200个样本

窗口覆盖：至少 200/50 = 4 个窗口完全在异常区域
→ 极高的检测置信度
```

### 🔄 **4. TAKEOVER - 完美检测 (0.998-1.000 → 1.000)**

#### **Takeover + pos_vel_acc 的异常**

Takeover 本来就强制使用 pos_vel 或 pos_vel_acc，所以影响较小。

**异常来源：**

1. **参考轨迹偏离真实轨迹**
   ```python
   # 参考轨迹
   p_ref(t) = p_real(t) + M·g(t)·d̂
   
   # 一阶跟踪
   p'(t) = p'(t-1) + α·[p_ref(t) - p'(t-1)]
   
   # 即使速度/加速度重计算保持一致性
   # 但轨迹本身就偏离了正常路径
   ```

2. **跟踪动态产生的瞬态**
   - 跟踪过程有过冲、振荡
   - 产生异常的速度/加速度模式

3. **位置特征异常**
   - 偏离正常飞行轨迹
   - 即使运动学一致，位置序列仍异常

**为何达到完美检测？**
- 结合了 Drift 的持续偏离特性
- 加上一阶动态的瞬态响应
- 多重异常叠加 → 极易检测

### 🎬 **5. REPLAY - 仍然最难 (0.504-0.548 → 0.638-0.831)**

#### **为何仍然难检测？**

```python
# Replay：用真实历史轨迹片段替换当前轨迹

# 关键：donor segment 本身来自真实飞行数据
# 内部的 p, v, a 关系完美！

donor_segment = real_trajectory[t_a : t_b]

# pos_vel_acc 重计算：
# v[i] = (p[i] - p[i-1]) / Δt
# a[i] = (v[i] - v[i-1]) / Δt

# 因为 p 序列来自真实数据
# → 计算出的 v, a 也接近真实值
# → 运动学一致性完美！
```

**唯一的异常：拼接点**

1. **Hard Stitching**
   ```
   Time:    [t_s-1]  [t_s]  [t_s+1] ... [t_e-1]  [t_e]  [t_e+1]
   Source:  real     donor  donor   ... donor    real   real
            ↓        ↓                            ↓      ↓
   Jump:         突变                         突变
   
   仅 2 个时间点异常（开始+结束）
   ```

2. **窗口稀释效应**
   ```
   窗口大小 = 50 samples
   异常样本 = 2 samples (拼接点)
   异常比例 = 4%
   
   → 大部分窗口特征仍然正常
   → 检测困难
   ```

#### **为何有所改善 (0.504 → 0.638, 0.548 → 0.831)？**

**关键改进：拼接点的速度/加速度突变更明显**

```python
# pos_only 时：
# 拼接点只有位置突变，速度/加速度保持原值
# → 可能速度与位置跳变方向不一致，但不明显

# pos_vel_acc 时：
# 拼接点的速度被强制重计算

# 例如：t_s 时刻从 real → donor
v(t_s) = [p_donor(t_s) - p_real(t_s-1)] / Δt

# 如果 donor 轨迹与 real 轨迹位置差异大
# → 速度会有明显跳变
a(t_s) = [v(t_s) - v(t_s-1)] / Δt
# → 加速度也会有尖峰
```

**Soft Stitching 更好检测：**
- 软拼接有 0.5 秒过渡
- pos_vel_acc 计算的速度/加速度在过渡区间仍有异常
- 5 个样本 (0.5s × 10 Hz) 的异常比 2 个样本更容易检测

**replay_other_soft (0.831) > replay_same_hard (0.638):**
- Soft 拼接的异常区间更长
- 其他航班的轨迹可能与当前有更多差异

## 统一机理总结

### 🔑 **pos_vel_acc 的双刃剑效应**

#### ✅ **优势：消除了运动学不一致性**
- 对高级攻击者更真实（会保持一致性）
- 公平的比较基准

#### ⚠️ **但引入了新的检测依据**

| 攻击类型 | pos_only 依赖特征 | pos_vel_acc 新特征 | 检测难度变化 |
|---------|-----------------|------------------|------------|
| **Delay** | 残差（不明显） | **速度时序错位** | 难 → 易 ⬆️ |
| **Step** | 残差爆炸 | **速度/加速度尖峰** | 易 → 易 ➡️ |
| **Drift** | 残差 + 偏离 | **持续速度偏离** | 易 → 更易 ⬆️ |
| **Takeover** | 轨迹偏离 | **轨迹偏离** | 易 → 更易 ⬆️ |
| **Replay** | 拼接点残差 | **拼接点速度突变** | 难 → 中等 ⬆️ |

### 📊 **检测器实际学到了什么？**

原以为检测器学的是：**运动学不一致性残差**

实际上检测器学到的是：**多维度异常模式**

1. **时序模式异常**
   - Delay: 速度序列不匹配当前时间
   - Step: 瞬时尖峰模式
   
2. **持续模式异常**
   - Drift: 持续的速度偏离
   - Takeover: 持续的轨迹偏离

3. **拼接异常**
   - Replay: 轨迹不连续

### 🎯 **为什么 CNN 能检测 pos_vel_acc 攻击？**

**关键：CNN 的时序特征学习能力**

```python
# CNN 在滑动窗口上学习
# Input: [50 samples × N features]

# 学到的模式：
1. 速度序列的时序一致性
   - 正常：速度平滑变化，符合飞行动力学
   - Delay: 速度来自过去，与当前阶段不符
   
2. 速度-位置的协调性
   - 正常：速度方向与轨迹方向一致
   - Drift: 额外的速度分量，方向异常
   
3. 尖峰检测
   - 正常：平滑的加速度变化
   - Step: 瞬时极大的加速度峰值
   
4. 轨迹一致性
   - 正常：位置序列平滑
   - Replay: 拼接点突变
```

## 实验设计的成功之处

### ✅ **统一 pos_vel_acc 揭示了真实检测能力**

1. **消除了实验偏差**
   - 所有攻击使用相同的一致性策略
   - 公平的性能比较

2. **更接近真实威胁**
   - 高级攻击者会维持运动学一致性
   - 测试检测器的真实鲁棒性

3. **发现了新的检测机制**
   - Delay 的时序错位特性
   - Step 的尖峰特性
   - 都不依赖残差特征

### 🎓 **论文可以论证的点**

1. **检测器不仅依赖残差**
   - 能够检测运动学一致的攻击
   - 学习了多维度时序模式

2. **攻击隐蔽性的真正决定因素**
   - 不是"是否保持一致性"
   - 而是"攻击机制是否引入时序/空间异常"

3. **Replay 仍然是最难检测的攻击**
   - 因为使用真实轨迹片段
   - 内部完全正常，只有边界异常
   - 需要更高级的检测方法（跨航班对比、重复检测）
