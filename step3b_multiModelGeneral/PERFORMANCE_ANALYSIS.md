# 模型表现分析报告

## 📊 实验结果总结

### 整体性能
所有7个模型在测试集上都达到了**接近完美**的表现：
- ROC-AUC: 1.0 (除TCN为0.9956)
- Precision/Recall/F1: 几乎全部为1.0
- 混淆矩阵：几乎零误报和零漏报

## ⚠️ 存在的问题分析

### 1. **测试集攻击样本严重不足**

**问题根源：**
```
测试集分布：
- 总航班数：32
- 被攻击航班：仅3个 (9.4%)
- 攻击类型：只有3种 (step, drift_ramp, drift_sigmoid)
- 缺失攻击：delay, takeover_step, takeover_ramp 在测试集中完全没有！
```

**影响：**
- ❌ **测试集不具代表性**：只测试了6种攻击中的3种
- ❌ **无法评估泛化能力**：缺失的3种攻击类型(delay, takeover系列)完全没有被测试
- ❌ **per_attack_metrics.json只有3种攻击**：无法全面评估
- ❌ **统计显著性不足**：每种攻击只有1个航班样本

### 2. **窗口级别样本不平衡**

**当前分布：**
```
测试集窗口：
- 总窗口数：7,576
- 攻击窗口：227 (3.0%)
- 正常窗口：7,349 (97.0%)
```

**问题：**
- 正负样本比例 1:32，严重不平衡
- 虽然使用了pos_weight，但3%的正样本比例可能仍然过低
- 模型可能倾向于预测"正常"

### 3. **任务可能过于简单**

**训练集特点：**
```
训练集：146航班，73个被攻击 (50%)
- 每种攻击类型：12-13个航班
- 攻击均匀分布
- 一致性模式：只用pos_vel_acc（位置、速度、加速度一致）
```

**可能的原因：**

#### a) **攻击模式太明显**
- **pos_vel_acc一致性**：攻击同时修改位置、速度、加速度，产生强烈的特征模式
- **固定攻击参数**：magnitude只有[5, 15, 30]米三种，duration固定，很容易被学习
- **明显的跳变**：Step攻击和Takeover攻击产生明显的跃变信号

#### b) **特征工程可能引入标签泄漏**
检查`feature_engineering.py`中的特征：
- 如果计算了"position跳变"、"速度突变"等衍生特征
- 这些特征可能直接暴露攻击的存在

#### c) **窗口平衡策略**
```python
TRAIN_POS_RATIO = 0.35  # 训练集强制35%正样本
VAL_POS_RATIO = 0.03    # 验证集只有3%
TEST_POS_RATIO = 0.03   # 测试集只有3%
```
- 训练集35%正样本比例较高，可能导致模型过度关注攻击特征
- 验证集和测试集3%的比例与真实分布接近，但差距太大

### 4. **训练/验证不匹配**

观察训练曲线：
```
Train loss: 0.211 → 0.025 (持续下降)
Val loss:   0.017 → 0.011 (在低位波动)
Val PR-AUC: 0.993 → 0.999 (始终接近1.0)
```

**现象：**
- 验证集从epoch 1就达到了98%+ PR-AUC
- 验证loss远低于训练loss（0.017 vs 0.211在epoch 1）
- 这种"验证比训练更简单"的情况不正常

**可能原因：**
1. **窗口平衡导致**：训练集35%正样本 vs 验证集3%正样本
   - 训练集难度更高（需要在更balanced的数据上学习）
   - 验证集难度更低（正样本稀少，容易全预测为0）

2. **测试集攻击样本太少**：
   - 只有3个被攻击航班
   - 模型很容易在这么小的测试集上"运气好"

### 5. **缺少真实挑战**

**测试集中缺失的攻击类型：**
- ❌ `delay`: 延迟攻击（GPS时间延迟）
- ❌ `takeover_step`: 接管式攻击（阶跃）
- ❌ `takeover_ramp`: 接管式攻击（渐变）

这3种攻击可能比现有的3种（step, drift_ramp, drift_sigmoid）更难检测。

## 🔍 是否过拟合？

### 传统意义的过拟合：❌ **不明显**
- Train loss持续下降
- Val loss也在下降（没有上升）
- Val PR-AUC持续提升

### 但存在更严重的问题：✅ **数据/任务问题**

**不是模型过拟合，而是：**
1. **测试集代表性不足**：只测试了一半的攻击类型
2. **任务过于简单**：攻击特征太明显
3. **评估不充分**：测试样本量太小（每种攻击只有1个航班）
